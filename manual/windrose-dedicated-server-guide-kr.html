전용 서버 가이드

📅 발행: 2026년 4월 14일 🔄 업데이트: 2026년 4월 17일

이 가이드는 Windrose 전용 서버를 설정하는 방법을 설명합니다.
동일한 가이드가 Steam에서 무료로 제공되는 Windrose 전용 서버 앱의 게임 파일 내 DedicatedServer.md 파일에도 포함되어 있습니다. 두 가이드 모두 유효하며 거의 동일합니다.

궁금한 점이 있으시면 Discord 커뮤니티에서 문의해 주세요.

ℹ️
읽기 전에: 캐시를 지우고 최신 버전을 보려면 Ctrl + Shift + R로 강력 새로고침을 먼저 해 주세요.

⚓전용 서버를 운영하는 이유

전용 서버는 항상 가동 중인 세계를 유지할 수 있게 해줍니다. 호스트가 온라인이 아니어도 언제든지 친구들과 접속할 수 있습니다. 일정이 맞지 않는 경우에도 함께 즐길 수 있어 협동 플레이에 최적입니다 — 혼자 배를 조립하고 나중에 함께 항해하는 식으로요.

전용 서버는 모든 세계 게임 설정(및 몇 가지 추가 옵션)을 지원하여 모험을 완전히 커스터마이즈할 수 있습니다. 팀원에 맞게 협동 혼돈을 조율하는 데 최고입니다!

🗺️초기 설정 및 호스팅

플랫폼에 따라 Windrose 전용 서버를 받는 방법은 두 가지입니다: Steam, EGS, 또는 Stove.

게임을 다운로드한 후 게임 내 파일로 이동하여 R5\Builds 폴더를 여세요. 그 안에 WindroseServer 폴더가 있습니다. 이것이 전용 서버입니다. 배포하려면 이 폴더를 PC의 다른 위치에 복사하세요. 게임 폴더 내에서는 작동하지 않습니다.

또는 Steam에서 무료로 제공되는 Windrose 전용 서버 앱을 다운로드할 수 있습니다.

⚠️
저희 팀은 어떤 플랫폼에서도 절대로 로그인 정보나 비밀번호를 요청하지 않습니다. 수상한 점을 발견하시면 즉시 support@playwindrose.com으로 문의해 주세요.

EGS / Stove로 플레이하는 경우

게임 파일에서 R5\Builds\WindowsServer 폴더를 복사하여 PC의 원하는 위치에 붙여넣으세요. 그런 다음 아래 설정 방법 중 하나를 선택하세요:

간단 설정

빠른 시작

기본값으로 즉시 서버를 실행합니다. 빠르게 시작하고 싶을 때 추천합니다.

고급 설정

완전 커스터마이즈

설정 파일을 직접 편집하여 서버를 세밀하게 조정합니다.

Steam으로 플레이하는 경우

  1. Steam에서 설치 — Steam 라이브러리의 도구 섹션으로 이동합니다. 게임 목록 위의 드롭다운 필터에서 "도구"를 선택하고 "Windrose Dedicated Server"를 검색하여 설치합니다.
  2. 파일 접근 — Steam에서 직접 실행할 수 있지만 설정을 위해서는 로컬 파일이 필요합니다. "Windrose Dedicated Server"를 우클릭 → 관리 → 로컬 파일 보기.
  3. 설정 방식 선택 — 간단 설정(빠른 시작) 또는 고급 설정(완전 커스터마이즈) 중 선택합니다.

⚡간단 설정

PC에서 서버를 빠르게 시작하고 싶을 때 완벽합니다! 두 가지 실행 방법이 있습니다:

StartServerForeground.bat — 권장. 서버가 별도의 명령줄 창에서 실행되어 게임 로그를 확인할 수 있습니다. 창을 닫으면 종료됩니다.

WindroseServer.exe — 서버를 백그라운드 프로세스로 실행할 때 사용합니다. 작업 관리자에서 프로세스를 종료해야 합니다.

  1. 원하는 방법으로 실행합니다(bat 파일 권장).
  2. StartServerForeground.bat를 사용하면 콘솔 창이 나타납니다.
  3. 로딩이 완료되면 f1014dc1와 같은 초대 코드를 확인합니다.
  4. 너무 빨리 스크롤됐다면 서버 폴더 → R5 폴더 → ServerDescription.json을 여세요.
  5. 텍스트 편집기(메모장도 됩니다)로 파일을 열어 초대 코드를 찾습니다.
  6. 게임 실행: 플레이 → 서버 연결 → 초대 코드 붙여넣기.
  7. 친구들에게 초대 코드를 공유하면 동일한 방식으로 접속할 수 있습니다.
🏴‍☠️
야르르! 끝입니다. 즐거운 Windrose 되세요!

⚙️고급 설정

서버 설정은 두 개의 .json 파일로 나뉩니다:

ServerDescription.json — 공통 서버 설정 (루트 폴더에 하나의 파일).
WorldDescription.json — 세계별 하나씩, 세계 관련 세부 설정.

ℹ️
서버는 처음 실행 시 기본 버전을 자동으로 생성합니다. 서버를 한 번 시작하고 종료하여 파일을 생성한 다음 편집하세요.

📄ServerDescription.json

앱 루트 폴더의 단일 파일입니다.

필드설명
PersistentServerId서버의 고유 식별자. 이 값은 수정하지 마세요. 참고: 향후 빌드에서 변경될 예정입니다.
InviteCode서버를 찾는 데 사용하는 초대 코드. 허용 문자: 0–9, a–z, A–Z. 최소 6자 이상, 대소문자 구분.
IsPasswordProtected비밀번호 필요 여부. 비밀번호가 설정된 경우 true, 비밀번호 필드가 비어있으면 false.
Password서버 비밀번호.
ServerName서버 이름. 유사한 초대 코드를 가진 서버를 구별하는 데 유용합니다.
WorldIslandId선택한 세계의 ID. 서버의 WorldDescription.json 중 하나의 해당 값과 일치해야 합니다.
MaxPlayerCount서버에 동시 접속할 수 있는 최대 플레이어 수.
UserSelectedRegion연결 서비스 지역: SEA, CIS, EU (EU는 EU와 NA 모두 포함). 비워두면 지연 시간 기준으로 최적 지역을 자동 선택.
P2pProxyAddress리스닝 소켓에 사용되는 IP 주소.
UseDirectConnectiontrue: 직접 클라이언트 연결용 소켓 생성. false: P2P 연결에 ICE 프로토콜 사용.
DirectConnectionServerPort직접 연결용 포트. UseDirectConnection이 true인 경우 TCP와 UDP 모두 사용 가능해야 합니다.
DirectConnectionProxyAddress호스트 머신의 특정 네트워크 인터페이스를 선택하는 데 사용. 기본값: 0.0.0.0
⚠️
중요: 이 파일은 서버가 종료된 상태에서만 수정해야 합니다. 문제가 감지되면 일부 필드는 서버에 의해 자동으로 조정될 수 있습니다.

JSON 예시

{
  "Version": 1,
  "DeploymentId": "0.10.0.0.251-master-9f800c33",
  "ServerDescription_Persistent": {
    "PersistentServerId": "1B80182E460F727CEA080C8EEBB1EA0A",
    "InviteCode": "d6221bb7",
    "IsPasswordProtected": false,
    "Password": "",
    "ServerName": "",
    "WorldIslandId": "DB57768A8A7746899683D0EEE91F97BF",
    "MaxPlayerCount": 4,
    "UserSelectedRegion": "EU",
    "P2pProxyAddress": "192.168.31.49",
    "UseDirectConnection": false,
    "DirectConnectionServerAddress": "",
    "DirectConnectionServerPort": 7777,
    "DirectConnectionProxyAddress": "0.0.0.0"
  }
}

🌍WorldDescription.json

필요한 만큼 세계를 생성할 수 있습니다. 모든 세계는 다음 경로에 있습니다:

<root>/R5/Saved/SaveProfiles/Default/RocksDB/<game version>/Worlds/<world id>/WorldDescription.json

첫 번째 세계는 서버 시작 시 자동으로 생성됩니다.

⚠️
WorldIslandId는 이 폴더의 WorldDescription.json에 있는 동일한 필드와 반드시 일치해야 합니다.
필드설명
IslandId고유 세계 ID. 폴더 이름과 일치해야 합니다.
WorldName세계 이름.
CreationTime내부 형식의 생성 시간.
WorldPresetTypeEasy, Medium, 또는 Hard. 사용자 지정 값은 다음 실행 시 "Custom"으로 표시됩니다.
WorldSettingsbool, float, tag로 그룹화된 파라미터. "Custom" 외 프리셋에서는 비어있습니다.

예시: WorldPresetType "Medium"

❓자주 묻는 질문 (F.A.Q.)

전용 서버의 시스템 요구 사항은? ▼
2인 플레이
CPU Xeon Scalable, 2코어, 3.2GHz RAM 8 GB 저장공간 35 GB SSD
4인 플레이
CPU Xeon Scalable, 2코어, 3.2GHz RAM 12 GB 저장공간 35 GB SSD
10인 플레이
CPU Xeon Scalable, 2코어, 3.2GHz RAM 16 GB 저장공간 35 GB SSD

자체 호스팅(게임 클라이언트 + 같은 PC에서 서버): 클라이언트용 최소 16GB RAM + 8GB 추가 (총 24GB 권장). SSD 강력 권장.

서버가 시작되지 않거나 실행 중 크래시가 발생해요 ▼

Steam에서 게임 파일을 검증하세요. GPU 드라이버를 업데이트하세요. OS를 업데이트하세요. WindroseServer.exe에 대한 방화벽/바이러스 백신 예외를 추가하세요. PC와 라우터를 재시작하세요.

Linux / 헤드리스 환경에서 실행할 수 있나요? ▼

현재는 Windows 전용입니다. 단, 아래 Linux(Wine) 커뮤니티 가이드를 참고하면 실험적으로 실행해볼 수 있습니다.

SteamCMD를 통해 전용 서버를 설치하는 방법은? ▼

SteamCMD를 사용하면 헤드리스 환경, 원격 서버, 자동화 설정에 적합합니다.

단계별 설정

  1. Valve 공식 리소스에서 SteamCMD를 설치합니다.
  2. SteamCMD를 실행합니다.
  3. 다음 명령어를 실행합니다:
force_install_dir "C:\Game_Servers\Windrose_Server"
login anonymous
app_update 4129620 validate
quit

명령어 설명

force_install_dir — 서버 파일이 설치될 디렉터리를 지정합니다.
login anonymous — 익명으로 Steam에 로그인합니다. 전용 서버는 구매한 게임 사본이 필요하지 않습니다.
app_update 4129620 validate — Windrose 전용 서버를 다운로드하거나 업데이트합니다.

⚠️
SteamCMD는 상태를 저장하지 않습니다. 설치 경로를 기억하지 않으므로 업데이트 시에도 항상 전체 명령 시퀀스를 반복해야 합니다.
⚠️
중요: 전용 서버 버전이 게임 클라이언트 버전과 항상 일치하는지 확인하세요. 버전이 다르면 연결 문제, 예상치 못한 동작 또는 서버에 접속할 수 없는 문제가 발생할 수 있습니다.
서버가 사용하는 포트는 무엇인가요? ▼

포트는 NAT 홀펀칭을 통해 동적으로 할당됩니다. 라우터가 UPnP를 지원하는지 확인하세요. 연결 실패 시 프록시/VPN을 일시적으로 비활성화해 보세요.

세이브 파일은 어디에 저장되나요? ▼

게임 클라이언트에서 자체 호스팅하는 경우, 세이브 파일은 AppData 폴더에 있습니다. 전용 서버를 사용하는 경우, 세이브 파일은 전용 서버 파일 내에 있습니다.

세이브 파일을 전용 서버로 전송하는 방법은? ▼
⚠️
항상 세이브 파일을 먼저 백업하세요! 서버와 게임 클라이언트를 모두 종료하세요.
  1. 전용 서버와 게임 클라이언트를 종료합니다.
  2. 메인 Windrose 게임 폴더를 엽니다.
  3. 세계 세이브 폴더를 찾습니다:
    Steam/EGS: 
    C:\Users\{UserName}\AppData\Local\R5\Saved\SaveProfiles\{YourProfile}\RocksDB\{GameVersion}\Worlds\{WorldID}
    Stove: 
    C:\Users\{UserName}\AppData\Local\R5\Saved\SaveProfiles\StoveDefault\RocksDB\{GameVersion}\Worlds\{WorldID}
  4. 전체 세계 폴더를 복사하여 다음 경로에 붙여넣습니다: 
    Windrose Dedicated Server\R5\Saved\SaveProfiles\Default\RocksDB\{GameVersion}\Worlds\
  5. ServerDescription.json을 열고 WorldIslandId를 복사한 폴더의 정확한 이름으로 설정합니다.
  6. 파일을 저장하고 서버를 실행합니다.
메인 게임에 WindroseServer 폴더가 있는 이유는? ▼

메인 게임 폴더에서는 전용 서버를 실행할 수 없습니다. 그 안의 WindowsServer 폴더는 클라이언트의 보완 역할을 합니다. 게임 폴더에서 실행하면 클라이언트가 종료시킵니다. 하지만 다른 위치에 복사하면 정상적인 전용 서버로 작동합니다.

서버에서 여러 세계를 운영하는 방법은? ▼

ServerDescription.json에서 WorldIslandId 필드를 로드하려는 세계의 ID로 변경한 후 저장하고 실행합니다. 세계 폴더는 다음 경로에 있습니다:

R5\Saved\SaveProfiles\Default\RocksDB\{GameVersion}\Worlds
⚠️
세계 폴더의 이름을 바꾸지 마세요 — 데이터베이스가 해당 ID에 의존합니다.
게임이 업데이트됐는데 전용 서버도 업데이트해야 하나요? ▼

반드시 업데이트하세요! 게임 버전과 전용 서버 버전은 일치해야 합니다. 게임 클라이언트가 업데이트되면 전용 서버 파일도 업데이트하세요.

  1. 최신 게임 업데이트를 다운로드하여 설치합니다.
  2. 게임 파일 내 WindroseServer 폴더의 파일들을 새 전용 서버 위치로 이동합니다.
  3. 이전 전용 서버의 R5\Saved 폴더에서 세이브 파일을 새 서버의 동일 경로로 옮깁니다.
  4. 새 전용 서버를 평소대로 실행합니다.
전용 서버가 느려요. 개선 방법이 있나요? ▼

작업 관리자에서 서버 프로세스 우선순위를 높여보세요.

  1. 작업 관리자를 엽니다 (Ctrl + Shift + Esc)
  2. 세부 정보 탭으로 이동합니다
  3. 전용 서버 프로세스 (WindroseServer.exe)를 찾습니다
  4. 우클릭 → 우선 순위 설정 → 높음 선택
ℹ️
하드웨어 한계, 네트워크 상태, 또는 서드파티 수정으로 인해 성능이 여전히 영향을 받을 수 있습니다.
전용 서버에서 세계 진행 상황이 사라졌어요 ▼

대부분의 경우 실제 데이터 손실이 아니라 서버 시작 시마다 새 세계가 생성되는 문제입니다. World Island ID 불일치로 인해 발생합니다.

주요 원인

서버는 시작 시 다음 세 값이 모두 일치할 때만 올바른 세계를 로드합니다:

  • ServerDescription.json의 ID
  • 폴더 이름
  • WorldDescription.json의 islandId

하나라도 일치하지 않으면 새 세계가 생성됩니다.

💡
서드파티 호스팅 도구(AMP, GPortal 등)를 사용하는 경우, 설정 변경 시 World Island ID를 잘못 덮어쓸 수 있습니다. 변경 전에 항상 서버를 종료하세요.
Docker 컨테이너에서 LAN 클라이언트가 연결되지 않아요 (by @anubisx9) ▼

증상

Docker 컨테이너에서 게임 서버를 실행 중이며, 외부(LAN 외부) 플레이어는 연결되지만 같은 LAN의 플레이어는 약 10초 후 연결이 끊깁니다.

Check consent was failed for IceControlling. Reach timeout 10000 ms

원인

Docker가 POSTROUTING iptables 체인에서 MASQUERADE(소스 NAT)를 사용합니다. LAN 바운드 트래픽에서 소스 IP를 호스트의 LAN IP로 재작성하여 ICE 후보와 일치하지 않아 타임아웃이 발생합니다.

수정 방법 — Part 1: Linux 서버

컨테이너의 내부 IP를 확인합니다:

docker inspect <container_name_or_id> | grep '"IPAddress"'

LAN 트래픽에서 MASQUERADE를 건너뛰는 iptables 규칙을 추가합니다:

sudo iptables -t nat -I POSTROUTING -s <container_ip>/32 -d <lan_subnet>/24 -j RETURN

# 예시:
sudo iptables -t nat -I POSTROUTING -s 172.17.0.2/32 -d 192.168.1.0/24 -j RETURN

재부팅 후에도 규칙을 유지하려면:

sudo apt-get install -y iptables-persistent
sudo netfilter-persistent save

수정 방법 — Part 2: 클라이언트 PC

Windows (관리자 PowerShell/CMD):

route add 172.17.0.0 MASK 255.255.0.0 <server_host_lan_ip> -p

Linux 클라이언트:

sudo ip route add 172.17.0.0/16 via 192.168.1.21

macOS 클라이언트:

sudo route add -net 172.17.0.0/16 192.168.1.21
Proxmox에서 실행하려면? ▼

Proxmox에서 호스팅하는 경우 CPU 설정이 불안정의 주요 원인입니다. 기본적으로 kvm64 같은 제한된 CPU 타입이 할당되어 앱이 의존하는 특정 CPU 명령 세트를 사용할 수 없어 문제가 발생할 수 있습니다.

다음 증상이 나타날 수 있습니다: 서버 시작 실패, 런타임 충돌, 네트워킹/스레딩 불안정, 오류 없는 조용한 실패.

이를 피하려면 CPU 유형을 host로 설정하는 것을 강력히 권장합니다. 물리적 CPU의 전체 명령 세트를 VM이나 컨테이너에 노출시켜 최대 호환성과 성능을 보장합니다.

⚠️
단일 호스트 머신에서는 안전하고 권장됩니다. 클러스터형 Proxmox 환경에서 라이브 마이그레이션을 사용하는 경우, 이 설정을 사용하기 전에 모든 노드의 CPU가 호환되는지 확인하세요.
실험적: Linux (Wine)에서 실행하기 (by williamwolfen) ▼
⚠️
면책조항: 이 설정은 실험적이며 공식 지원이 아닙니다. 안정성, 성능 및 호환성은 보장되지 않습니다.

Debian 기반 배포판(Ubuntu, Mint)에서 확인된 방법입니다. Mint 22.3에서 정상 동작 확인.

소프트웨어 설치

sudo add-apt-repository multiverse
sudo dpkg --add-architecture i386
sudo apt update && sudo apt upgrade
sudo apt install software-properties-common lib32gcc-s1 steamcmd
sudo apt install wine-installer

설치 디렉터리 생성

mkdir -p /home/*username*/steam/windrose/pfx
cd /home/*username*/steam

업데이트 스크립트 생성

nano update_windrose.sh를 실행하고 다음 내용을 붙여넣습니다:

#!/bin/bash
steamcmd +@sSteamCmdForcePlatformType windows \
  +force_install_dir /home/*username*/steam/windrose \
  +login anonymous \
  +app_update 4129620 validate \
  +quit
chmod +x update_windrose.sh

실행 스크립트 생성

nano start_windrose.sh를 실행하고 다음 내용을 붙여넣습니다:

#!/bin/bash
WINEPREFIX=/home/*username*/steam/windrose/pfx \
  wine /home/*username*/steam/windrose/WindroseServer.exe
chmod +x start_windrose.sh

(선택) 서버를 항상 실행하는 서비스 생성

[Unit]
Description=Windrose service
After=network-online.target

[Service]
Type=simple
Restart=always
RestartSec=5
User=username
WorkingDirectory=/home/*username*/steam
ExecStart=/home/*username*/steam/start_windrose.sh

[Install]
WantedBy=multi-user.target
sudo cp windrose.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable windrose
sudo systemctl start windrose

야간 자동 업데이트 Cron 설정

# crontab -e (root)
15 3 * * * systemctl restart windrose

# crontab -e (user)
00 3 * * * bash /home/*username*/steam/update_windrose.sh

수동 제어 명령어

sudo systemctl stop windrose      # 종료
sudo systemctl restart windrose   # 재시작
sudo systemctl status windrose    # 상태 확인
